Security Checklist for Vibecoded Apps

October 19, 2026 · José Antonio Nicolás Navarro

AI coding assistants make it possible to go from idea to deployed app in an afternoon. The problem is that they optimize for "it works", not for "it's safe". The same patterns show up again and again: keys shipped to the browser, databases with no access rules, endpoints that trust whatever the client sends.

This isn't theoretical. In early 2026, Wiz found that Moltbook, a social network for AI agents whose creator said he hadn't written a single line of code, shipped a Supabase key in its client-side JavaScript with no database-level protection behind it. Anyone could read and write the database, including private messages, user emails and over a million API keys.

This is the checklist I go through before a vibecoded app touches real users or real data. None of it is exotic. Most of it takes minutes. Tick items as you go: progress is saved in your browser.

If you only do three things: keep secrets off the client, enforce authorization on the server (RLS included), and rate limit anything that costs you money.

Shipping fast is fine. Shipping fast with an open database is how your app ends up in someone's breach writeup. Run through this list once before launch, and again whenever the AI rewrites something important.
